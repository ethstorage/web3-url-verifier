EthStorage · Verifiable Frontends

The problem

  • Trust stops at the contracts — the frontend is just a hosted file
  • Compromise it and funds drain, however sound the contracts are
  • The user has no way to tell

EthStorage · Verifiable Frontends

The idea

  • Put the frontend on-chain, addressed by web3:// — ERC-4804
  • Same keys as the contracts → trust root already in place
  • Light client checks the bytes against chain state
  • The gateway stays in the path, but drops out of the trust model

EthStorage · Verifiable Frontends

It works today

  • End to end — our CLI fetches, Colibri verifies, result reported
  • Two storage models, one verification path Ethereum-native · vitalikblog.eth  /  EthStorage + L1 · eth-store.eth
  • Chrome extension built — every response body is reachable, via CDP
  • Verification not yet wired into it. That's next.
